## 2. Мета роботи

Створити Python-пакет, який читає CSV, перетворює текстові поля на типізовані значення,
будує звіт за допомогою списків, словників і множин і записує його у файл. Помилки мають
оброблятися явно, а поведінка — перевірятися pytest.

Досягнуто:

- пакет `kzp_lab06` із модулями `errors`, `loader`, `analysis`, `reporting`, `cli`;
- консольна команда `kzp-lab06` і запуск `python -m kzp_lab06.cli`;
- 45 тестів pytest, чистий `ruff check` і `ruff format --check`;
- wheel збирається, встановлюється в окреме середовище й працює на трьох ОС;
- завдання із зірочкою: потокова обробка великого CSV з вимірюванням пам'яті.

## 3. Формат CSV

Заголовок: `name,form,price,days_left,prescription` (UTF-8, роздільник — кома).

| Поле | Текст у CSV | Тип після перетворення | Правило |
|------|-------------|------------------------|---------|
| `name` | `Парацетамол` | `str` | непорожній, зайві пробіли прибираються |
| `form` | `Таблетки` | `str` | непорожній, нижній регістр → `таблетки` |
| `price` | `45.50` | `float` | скінченне, ≥ 0 |
| `days_left` | `365` | `int` | ціле, ≥ 0 |
| `prescription` | `false` | `bool` | `true/false`, `yes/no`, `так/ні`, `1/0` |

Приклад екранованого рядка (кома й лапки в назві):

```text
"Мазь ""Левомеколь"", 40 г",мазь,89.75,14,false
```

`csv.DictReader` повертає значення `Мазь "Левомеколь", 40 г`. Простий `split(",")` дав би шість
частин замість п'яти.

**Правило порожнього входу**: файл лише із заголовком є коректним і дає звіт з нулями й
«немає даних». Повністю порожній файл (без заголовка) спричиняє `DataError("порожній CSV:
немає рядка заголовка")`.

Вхідний файл `data/input.csv` має 11 записів. Серед них дублікат назви «Парацетамол»,
межові терміни 30 і 31 день, термін 0, форма «Таблетки» з великої літери й назва з комою
та лапками.

## 4. Структура модулів

```text
CSV → loader.py → list[Medicine] → analysis.py → dict-підсумок → reporting.py → текстовий файл
         ↓                                                              ↑
      DataError ──────────────────────────→ cli.py (stderr, код завершення)
```

| Модуль | Призначення |
|--------|-------------|
| `errors.py` | `DataError(ValueError)` — очікувана помилка вхідних даних |
| `loader.py` | `iter_records` (генератор) і `load_records`: `DictReader`, перевірка заголовка, перетворення та перевірка кожного поля; `TypedDict Medicine` описує запис |
| `analysis.py` | `expiring_soon`, `count_by_form`, `unique_forms`, `nearest_expiry`, `average_price`, `make_summary`, `summarize_stream` — чисті функції без вводу-виводу |
| `reporting.py` | `format_report` (текст), `write_report` (файл) |
| `cli.py` | `argparse`, виклик конвеєра, повідомлення в stderr, коди завершення |
| `__init__.py`, `__main__.py` | версія з метаданих пакета; запуск `python -m kzp_lab06` |

Модулі не виконують код під час імпорту. Запуск відбувається лише в
`if __name__ == "__main__"` у `cli.py` та в `__main__.py`.

## 5. Перетворення даних

- **Список**: `load_records` повертає `list[Medicine]`; `expiring_soon` — відфільтрований і відсортований список.
- **Словник**: кожен запис — словник (`TypedDict Medicine`); `count_by_form` повертає `dict[str, int]`;
  підсумок `make_summary` — словник.
- **Множина**: `unique_forms` — `{record["form"] for record in records}`; `TRUE_VALUES`/`FALSE_VALUES` — `frozenset`.
- **Comprehensions**:
  - list — `[record for record in records if record["days_left"] <= threshold]`;
  - set — множина форм;
  - dict — `{form: counts[form] for form in sorted(counts)}` і метрики в `make_summary`;
  - генераторний вираз — `sum(1 for record in records if record["prescription"])`.
- **Типи**: `price` → `float`, `days_left` → `int`, `prescription` → `bool`, `name`/`form` →
  нормалізований `str`. Нескінченні значення (`nan`, `inf`) відкидаються через `math.isfinite`.

## 6. Функції

```python
def make_summary(
    records: list[Medicine],
    *metrics: str,                    # кортеж назв полів, для яких порахувати суму
    threshold: int = EXPIRY_THRESHOLD,  # типовий параметр (30), лише іменований
    **labels: str,                    # словник підписів «поле → текст у звіті»
) -> dict[str, object]:
```

Приклад виклику:

```python
make_summary(records, "price", "days_left", price="Сума цін")
# metrics == {"Сума цін": 1590.95, "days_left": 796}, threshold == 30
make_summary(records, threshold=14)   # без метрик, інший поріг
```

Типові параметри мають і `expiring_soon(records, threshold=30)` та
`summarize_stream(records, threshold=30)`. Типових значень змінних типів (список, словник)
немає: такий об'єкт створювався б один раз і спільно використовувався між викликами.

## 7. Алгоритм аналізу

1. **Відбір**: `days_left <= 30` (межа включно: 30 — так, 31 — ні). Сортування за `(days_left, name)`.
2. **Агрегування за ключем**: `count_by_form` рахує кількість за `form` через `dict.get(form, 0) + 1`.
3. **Унікальні значення**: множина форм; у звіті вона виводиться відсортованою.
4. **Показники звіту**: найближчий термін — `min(..., key=(days_left, name), default=None)`; середня
   ціна — сума / кількість або `0.0` для порожнього набору; кількість рецептурних; сумарна вартість
   (метрика `price` через `*metrics`).
5. **Детермінованість**: ключі словника й форми — за абеткою, відібрані препарати — за терміном
   і назвою, числа — `:.2f`, у заголовку лише ім'я файла (без шляху, що залежить від ОС).
   Тест `test_cli_report_is_deterministic` перевертає порядок рядків CSV, а звіт лишається тим самим.

## 8. Обробка помилок

- `DataError(ValueError)` — єдиний тип очікуваної помилки даних.
- Повідомлення містить **номер рядка й назву поля**: `рядок 3, поле «price»: очікується число, отримано 'дорого'`.
- **Першопричина** зберігається через `raise DataError(...) from error`: `ValueError` від
  `float()`/`int()`, `OSError` від відкриття файла, `csv.Error` від пошкодженого CSV. Тести
  перевіряють `__cause__`.
- Голого `except:` немає, бо перехоплюються лише конкретні типи (`ValueError`, `OSError`,
  `csv.Error`). Неочікувана помилка не маскується й завершує програму з traceback.

| Ситуація | Повідомлення | Код CLI |
|----------|--------------|---------|
| успіх | звіт у stdout і файлі | **0** |
| файл не існує | `Помилка даних: не вдалося прочитати файл …` | **1** |
| порожній файл | `… порожній CSV: немає рядка заголовка` | **1** |
| відсутній стовпець | `… відсутні стовпці: prescription` | **1** |
| хибне / від'ємне число | `… рядок N, поле «price»: …` | **1** |
| відсутнє / порожнє значення | `… рядок N, поле «days_left»: значення відсутнє` | **1** |
| зайві значення в рядку | `… рядок N: зайві значення […]` | **1** |
| звіт не вдалося записати | `Помилка запису звіту: …` | **1** |
| хибні аргументи, вхід = вихід | повідомлення argparse / `вхідний файл і звіт мають бути різними файлами` | **2** |

Повідомлення виводяться в stderr. `cli.py` перемикає stdout і stderr на UTF-8
(`reconfigure`), бо консоль Windows може мати інше кодування.

**Завдання із зірочкою — потокова обробка.** `iter_records` — генератор: файл читається по
одному рядку, а `summarize_stream` будує той самий підсумок за один прохід, не зберігаючи всі
записи. `tools/memory_benchmark.py` генерує CSV через `itertools.count/islice/cycle` і вимірює
пік пам'яті через `tracemalloc`:

| 200 000 рядків (10,2 МБ) | пік пам'яті | час |
|--------------------------|-------------|-----|
| `load_records` + `make_summary` | 74,5 МБ | 5,3 с |
| `iter_records` + `summarize_stream` | 6,6 МБ | 4,1 с |

Результати однакові (перевіряє і скрипт, і тест `test_summarize_stream_matches_make_summary`).
Потоковий варіант теж тримає в пам'яті відібрані препарати з коротким терміном (≈ 8 % записів),
тож його пам'ять зростає пропорційно саме їм, а не всьому файлу. Вимірювання зроблено в
пісочниці з 2 ядрами; абсолютні числа залежать від машини, але порядок різниці стабільний.

## 15. Відповіді на контрольні питання

1. **pyproject.toml.** Єдиний опис проєкту: назва, версія, мінімальний Python, залежності
   (зокрема dev), система збирання, консольна команда й налаштування інструментів (pytest, ruff).
2. **Віртуальне середовище.** Ізолює залежності проєкту від системного Python і інших
   проєктів. Його можна відтворити з `pyproject.toml` на будь-якій машині, тому в git воно не потрапляє.
3. **newline="".** Передає обробку роздільників рядків модулю `csv`. Інакше Python сам
   перетворює `\r\n`, і перенесення всередині полів у лапках обробляються неправильно.
4. **Типи з DictReader.** Ключі й значення — рядки (`str`). Для коротшого рядка значення
   дорівнює `None`, зайві значення потрапляють у список під ключем `None`. Числа треба перетворювати самому.
5. **Чому не split(",").** Він не знає про лапки: кома в `"Мазь, 40 г"` розірве поле, подвоєні лапки
   не розкриються, перенесення рядка в лапках розірве запис.
6. **Список, словник, множина.** Список — упорядкована послідовність з повторами, доступ за
   індексом. Словник — пари «ключ → значення», пошук за ключем. Множина — унікальні елементи
   без порядку, швидка перевірка входження.
7. **Comprehension чи цикл.** Comprehension зручний для простого перетворення чи фільтра в
   один вираз. Цикл кращий, коли є кілька кроків, побічні дії, обробка винятків або складна логіка.
8. **\*args і \*\*kwargs.** `*args` — кортеж зайвих позиційних аргументів, `**kwargs` — словник
   зайвих іменованих.
9. **Змінний об'єкт як типове значення.** Він створюється один раз під час визначення функції
   й спільний для всіх викликів, тож зміни в одному виклику «перетікають» у наступні.
10. **raise ... from error.** Записує першопричину в `__cause__` нового винятку. Traceback
    показує обидва, і тести можуть перевірити причину.
11. **Чому модулі розділені.** Кожна частина має одну відповідальність, її легше тестувати
    окремо (аналіз — без файлів) і змінювати без впливу на інші. CLI лише з'єднує їх.
12. **with.** Гарантує, що файл буде закрито (дані скинуто на диск) при виході з блоку, навіть
    якщо всередині стався виняток.
13. **Детермінований порядок.** Однаковий вхід має давати однаковий файл, щоб звіти можна було
    порівнювати, тестувати посимвольно й не отримувати «зміни» лише через порядок множини чи словника.
14. **Порожній CSV.** Повністю порожній файл (немає заголовка), лише заголовок (0 записів, без
    ділення на нуль), відсутні стовпці. Кожен випадок має давати явну помилку чи коректний
    порожній звіт.
15. **Тест поведінки й реалізації.** Тест поведінки перевіряє результат, який бачить користувач
    (вихід функції, файл, код завершення), і не ламається від рефакторингу. Тест реалізації
    залежить від внутрішніх деталей і ламається при кожній їх зміні.
16. **Які файли знаходить pytest.** `test_*.py` і `*_test.py` у вказаних каталогах (у нас
    `testpaths = ["tests"]`), у них функції `test_*` і класи `Test*`; `conftest.py` — фікстури.
17. **Що перевіряє ruff.** Стиль PEP 8 (`E`, `W`), помилки на зразок невикористаних імпортів і
    невизначених імен (`F`), типові пастки (`B`), застарілий синтаксис (`UP`), порядок імпортів (`I`).
    `ruff format --check` перевіряє форматування.
18. **Коди завершення CLI.** `0` — успіх; `1` — очікувана помилка даних чи файла; `2` — хибні
    аргументи (стандарт argparse).
19. **Тести, аналізатор і пакетування в CI.** Вони ловлять різні проблеми: тести — помилки
    логіки, ruff — стиль і підозрілий код, збирання й встановлення wheel — помилки пакування
    (забуті модулі, неправильні метадані). І все це на кожній ОС.
20. **Що задекларувати в REPORT.** Формат і приклад вхідного CSV, повний очікуваний звіт, коди
    завершення, команди перевірок і їхні результати, посилання на CI й артефакти, версію й тег,
    використання ШІ.

## 16. Висновки

Створено модульний Python-пакет із CLI, явною обробкою помилок, детермінованим звітом,
тестами pytest, перевіркою ruff і wheel, який перевіряється в CI на трьох ОС і двох версіях
Python.

Для ЛР7 основою стануть `loader` (читання й перетворення CSV), `DataError`, формат звіту й
тести. Словникові записи `Medicine` буде замінено класами з `@property`, `@dataclass` для
результатів, спеціальними методами й двома підтипами препаратів зі спільним протоколом.
Формат звіту має лишитися тим самим.
